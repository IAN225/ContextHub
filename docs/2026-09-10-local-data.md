## 使用

书架顶部和手账顶部均可打开“本地数据”。

- **导出备份**：等待保存完成后下载 JSON，包含全部手账、完整轮次、Note 和版本、摘要和水位、记忆包配置、待归档内容、已落盘草稿以及已保存附件的 data URL 字节。备份文件包含原文等个人内容，请妥善保管。
- **恢复备份**：选择 JSON，检查备份时间和数量，勾选覆盖确认。正常情况下先发起当前数据的备份下载，再覆盖数据库并刷新；浏览器下载仍需用户确保保存成功。覆盖是整体替换，不是合并手账。单个文件上限 100 MB。
- **读取失败时恢复**：加载错误页有“从备份恢复”入口；由于当前数据不可读，此路径无法生成覆盖前备份，界面会明确说明。
- **回收站**：展示原文和 Note 的总数及到期数，可清理到期项，或勾选永久删除确认后清空全部。原文和 Note 原有恢复操作仍可使用。

备份不包含服务端模型 Key、浏览器 Cookie/真实投递凭据、尚未接收的 D1 队列或环境配置文件。外部附件地址只备份地址，不保证地址一直有效；现有导入流程未拿到的文件不会因备份补全。本次附件字节验证仅针对已经存入浏览器的附件。

## 数据规则

首次使用从空书架开始，可新建手账或导入对话；没有示例轮次、摘要、Note 或收件。读取旧数据库时保留既有内容，不按示例名称猜测并删除用户数据。数据库名称及主记录键保持兼容，不需要清除站点数据。

备份采用 `context-hub-backup` / version 1。导入先检查版本、重复键和 ID、主状态、草稿、附件、Note 历史及引用字段；不支持或损坏的数据在写入前报错。替换通过一次 IndexedDB 事务完成，失败时回滚。恢复后的数据库修订号阻止其他旧页面继续写入；请刷新旧页面后使用。

恢复后关闭每本手账的自动摘要和自动收件开关，保留当前与备份的收件去重记录，避免旧备份导致已处理投递重复出现。需要时可重新开启自动摘要和收件。回收站从恢复时再保留 30 天，原始删除时间仍保留。

回收站自动清理以删除时间满 30×24 小时为界：在应用加载完成、窗口重新获得焦点及每小时检查时执行。页面关闭时没有后台清理服务，下一次打开时补做。缺少或无效删除时间的旧记录不会自动删；未来时间也不会提前清理。弃用内容不属于回收站。

永久清理同步移除轮次附件、Note 历史、相应编辑草稿和 ID 引用；被删的摘要水位回退到原链中前一个仍存在的轮次。已经写入摘要正文的文字不会自动重写。主记录更新和草稿删除使用同一事务，失败保留原内容。
