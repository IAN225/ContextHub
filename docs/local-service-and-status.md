# 本地运行方式与功能边界 · 2026-09-11

2026-09-12 更新：新增服务器单管理员入口、域名 HTTPS 配置与 Ubuntu 服务模板，见 [服务器部署说明](server-deployment.md)。下文记录 9 月 11 日的本机运行方式；新增服务器流程尚待 Ubuntu 与真实证书验收。

## Sites、本机服务与远程连接的关系

当前沿用 Sites 的 Vinext 项目结构、构建流程和 Codex 内嵌浏览器预览，但没有部署到 Sites 云端，也没有创建正式站点。`demo/.openai/hosting.json` 只声明逻辑 D1 绑定 `DB`，没有 `project_id`。内嵌浏览器打开的是 `http://127.0.0.1:3000/`，展示本机进程提供的页面；关闭预览标签不会停止服务。

实际运行链路如下：

```text
本机浏览器 ───────────────────────────────────────> 127.0.0.1:3000
                                                   Wrangler / Workerd
                                                   + 本地 D1 持久化
Claude / ChatGPT → Cloudflare 临时 HTTPS 隧道
                   → 127.0.0.1:3001 MCP 网关 ───────> 127.0.0.1:3000
```

- `scripts/start-chatgpt.mjs` 是共用 OAuth 联调入口；`pnpm mcp:oauth`、`pnpm chatgpt`、`pnpm claude` 都调用它，并非分别启动三个服务。
- 它先检查 3000/3001 端口可用，再启动 `cloudflared`。Windows 优先使用被忽略的 `.wrangler/bin/cloudflared.exe`，否则从 PATH 查找 `cloudflared`；该程序需另行安装。
- 获得临时 HTTPS 地址后，脚本生成本次网关密钥，将地址和密钥写入被忽略的 `.env.mcp.local`，启动 3001 网关，并以 `CONTEXT_HUB_ENABLE_MCP_PUBLIC=1` 启动本机应用。
- `scripts/start-local.mjs` 用 `dist/server/wrangler.json` 运行 Wrangler，监听 `127.0.0.1:3000`，数据目录固定为 `.wrangler/state`，同时启动独立的后台任务执行器。可兼容读取 `.env.summary.local`；页面保存的模型配置由本机服务保管。
- `scripts/mcp-gateway.mjs` 仅转发 MCP、OAuth 与发现路由；页面、管理接口、模型设置和任务接口不经此隧道公开。MCP 仍需完成手账授权。

本地前端手账、草稿和邮箱通知位于这个 origin 的 IndexedDB；服务副本、任务、授权和未接收事件位于 `.wrangler/state`。两者不是同一份存储，都不随 Git 推送。换电脑先导出浏览器备份，再按备份说明迁移；复制代码不能迁移账号配置或授权。

## 换设备的标准启动

需要 Node.js 22.13+、pnpm；远程 OAuth 联调另需 Cloudflare 的 `cloudflared`。在仓库的 `demo/` 目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm db:init
pnpm mcp:oauth
```

只在本机使用时，最后一行换成 `pnpm start`；普通启动不打开临时公网入口。开发界面使用 `pnpm dev`，正式 MCP 联调使用上面的构建流程。启动前结束该项目占用端口的旧服务，不要同时运行两套应用。

打开 `http://127.0.0.1:3000/`，在目标手账的连接设置选择客户端并准备连接，复制地址到客户端。按“粘贴请求码 → 核对请求 → 批准此连接 → 返回授权页完成”的顺序授权。详细参数见 [MCP 使用说明](mcp.md)。

临时地址每次重启可能改变，应从连接页重新复制；新地址需要重新配置客户端并授权。服务停止、电脑关机或休眠期间无法访问。当前不是系统服务，没有开机自启或长期在线保证。

## 本次 Codex 会话实际如何启动和更新

1. 按 Sites 的本地运行流程复用现有项目，执行构建、迁移检查，再把 3000 地址打开到 Codex 预览。使用本机 Windows Node 24；没有申请 Sites 云端部署或改变已有数据目录。
2. Sites 的 `scripts/build-site.mjs` 会使用项目包管理器运行 build。本机 pnpm 前置检查因尚未批准的原生依赖构建脚本退出；本次使用已经安装可运行的依赖，直接执行 `node node_modules/vinext/dist/cli.js build` 完成相同应用构建，没有为此修改依赖审批设置。新设备应先正常完成依赖安装，不能假定跳过安装即可运行。
3. 构建后通过隐藏后台进程执行 `node scripts/start-chatgpt.mjs`。本机操作日志保存在 `.wrangler/chatgpt-background.out.log` / `.err.log`，主进程编号保存在 `.wrangler/chatgpt-background.pid`；这些是本次启动时记录的辅助文件，不是脚本自带的通用服务管理功能。
4. 保留已连通的 Claude 会话更新前端时，Windows 正在运行的 Wrangler 占用 `dist`，直接重新构建会因清理目录失败。为保持隧道地址，本次在被忽略的 `.wrangler/oauth-feedback-build` 中复制当前项目源码，使用指向已安装 `node_modules` 的目录联接完成独立构建。
5. 构建成功后，将生成的 Wrangler 配置中迁移目录改回原项目 `drizzle` 路径，再复制构建资源到原 `dist`，最后更新服务入口文件。原 Wrangler 自动重载；没有更换网关密钥、数据目录或 OAuth 授权。最后检查本机页面、HTTPS 发现接口均返回 200，并比对实际提供的前端资源与本次构建一致。

这是本次 Windows 开发会话的更新办法，尚未封装为通用热部署命令。日常换设备或允许中断时，优先停止原项目进程后重新构建、迁移、启动；不要删除 `.wrangler/state` 来解决构建目录占用，也不要将工作数据放入 `dist`。需要长期在线时应单独完成服务器部署与迁移。

## 尚未实现的功能

| 范围 | 当前边界 |
| --- | --- |
| 正式账号与多用户产品 | 没有云端注册/登录、团队成员、工作区共享和协作权限体系；OAuth 的本机 owner 会话用于当前手账授权，不等于产品账号。 |
| 稳定公网服务 | 没有正式域名、Ubuntu 生产部署、服务守护、开机自启和自动灾备流程；目前为按需临时 HTTPS 隧道。 |
| 自动跨设备同步 | 没有云端手账/草稿/附件同步；目前通过 JSON 备份迁移，模型设置与授权需另行配置。 |
| 语义检索 | 当前按关键词搜索，没有 embedding、向量库或语义召回。 |
| 多模态附件理解 | 实际保存可取得的文件、下载公开 HTTPS 附件、读取支持的 UTF-8 文本；不做图片 OCR、PDF/Office 内容解析、音视频转写或二进制模型输入。 |
| 完整富文本编辑 | 当前 Markdown 编辑与有限预览，不是完整 CommonMark 渲染器或所见即所得编辑器。 |
| 通知外发 | Note 创建通知是应用内邮箱通知；没有 SMTP 邮件、系统推送或短信。网页关闭期间的 MCP 创建，在网页再次接收变更时显示通知。 |
| 更广泛的身份协议 | 已有 OAuth DCR/PKCE/刷新轮换；尚无 CIMD/OIDC，也不自动支持任意厂商的回调。新增客户端须配置并验证注册表。 |

## 已实现但仍有验证或运行边界

- 原文导入、真实摘要请求、检查点、后台任务、附件保存、备份恢复、回收站和 7 项 MCP 工具已接入真实处理，不再是返回演示数据的占位功能。来源站点可能限流或拒绝访问，无法恢复客户端未发送的历史或平台私有附件。
- 2026-09-10 用户确认 ChatGPT 移动端实际创建 Note；2026-09-11 用户确认 Claude 连接及工具调用正常，并验证了创建、读取、精准替换、旧 revision 拒绝和 request_id 重放。不能据此宣称所有客户端、工具和平台组合都完成真实验收。
- `syncedAt` 是网页最后同步时间；MCP 创建/替换返回 Note 的 `updatedAt`，版本判断用 `revision`。首次创建通知和 Note、接收回执一起保存；不为升级前已接收的创建补发通知。
- 模型协议和后台持久化已实现；长对话压缩质量、提示词效果、模型上限及大量附件的存储成本仍需持续实测。服务中断的模型请求暂停待检查，不会自动重复发起可能计费的请求。
- 回收站自动清理依赖网页启动、聚焦与定时检查；关闭网页期间不执行，下次打开补做。后台队列能在关网页后运行，但本机服务必须继续运行。
- 主数据仍整体加载和保存，尚未拆成分记录数据库；大规模资料需要继续评估性能。实验性浏览器 WebMCP 有两个本地只读工具，它们与已实现的远程 MCP 服务不同，普通浏览器可能不支持。
- 本轮完成 121 项 Node 回归测试、类型检查、应用静态检查与构建；这些不能替代真实客户端或全部浏览器交互验收。
