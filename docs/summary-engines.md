# 摘要方案

摘要页一次显示一种方案，通过页签切换；切换只改变查看方式，不暂停另一套任务、不改变记忆注入来源。

| 方案                   | 用途                                                     |
| ---------------------- | -------------------------------------------------------- |
| 自定义压缩             | 原有分批、提示词编排、自定义工作台及历史恢复             |
| ReMeLight 风格（实验） | 固定结构的增量检查点：主题、事实、决定、进展、待办、来源 |

实验方案参考 [ReMeLight 的上下文检查点设计](https://github.com/agentscope-ai/ReMe/tree/reme_v3)，在 TypeScript 中独立实现预算分批、完整轮次、旧检查点合并和结构校验。未引入官方 Python ReMeLight、ReAct 执行器、文件工具或长期记忆索引，不宣称与官方引擎等价，也没有经过同模型效果基准验证。结构检查不能保证摘要事实完整或正确。

两套方案共享原文、附件和用户 Note；独立保存配置、模型连接、最多 30 个历史检查点、活跃摘要、保留窗口与处理位置。实验方案初始为空、自动压缩关闭，首次需要单独配置并手动开始；不会复制原方案的旧摘要或付费运行授权。模型凭据按账号与方案隔离，同一账号的同一方案在不同工作区可复用连接。自动压缩与每批检查也各自设置。

后台全局同时只执行一个任务。同一工作区可分别排队一项自定义压缩与一项实验压缩，暂停、失败、取消和恢复各自生效。两套都运行会产生两份模型调用费用。原文修改会使受影响的在途结果拒绝应用。

## 记忆注入

在摘要页点击“设为记忆注入来源”，或在记忆包页选择来源。默认沿用自定义压缩，选择随账号保存。memory_bootstrap 无参数时使用该选择，可选 engine=custom 或 reme 显式读取另一套；不会自动把两份摘要合并。近期原文与所选方案的处理位置配对。memory_search 默认只检索所选方案的摘要，原文和 Note 仍共用。

注入结果保留 content，追加 engine、summaryId、strategyVersion、coveredTurnIds、recentTurnIds、omittedTurnIds 和 status。元数据描述所选方案默认摘要与原文窗口的覆盖；用户在记忆包编排中自定义、替换或移除区块时，以 content 实际内容为准。尚无摘要时明确返回 no_summary，不回退另一套方案。

## 数据兼容

旧工作区的摘要字段继续归属自定义压缩。新实验状态按独立记录保存；旧原文、Note 和摘要不重写。D1 0006 增加任务方案字段和独立模型连接表，旧任务默认为 custom。新任务与 MCP 封套写入 v2，可读取 v0/v1；客户端协议升为 3，旧网页需刷新。使用仓库部署脚本执行备份、迁移、健康检查与失败恢复。
