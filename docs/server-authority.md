# 账号数据与后台执行边界

## 数据流

Web、MCP 和后台任务共用 `accounts.sqlite` 中的账号记录。`lib/application/server/workspaces.ts` 负责事务、账号状态、generation、revision、命令回执及删除时的授权和任务清理；领域 reducer 负责具体状态变化。请求处理器不保存另一份可写工作区。

```text
Web 命令 ───────────┐
MCP 工具 ───────────┼─ 应用服务 → 同一 SQLite 事务 → 账号记录 + 回执
任务结果 / 客户端投递 ┘
浏览器 ← 版本检查 / 账号快照 / 状态查询
```

`Workspace` 是可持久化的完整工作区；`SummaryView` 是选定摘要方案的投影。共享只读计算接受 `WorkspaceContext`。持久化命令不接受投影，摘要 reducer 只把对应轨道字段写回原工作区。Note 历史规则由 `lib/notes/operations.ts` 维护，Web 保存和 MCP 单字段替换保留各自的空白及相同内容处理语义。

Web 命令含操作 ID、generation 和依赖记录修订号。服务端拒绝未知命令、后台专用命令、原始业务记录覆盖及过期依赖。重复 ID 必须对应相同输入；响应丢失重试返回已提交回执。正文和关联草稿使用同一事务，浏览器保留未确认请求，不换新 ID 重发。

## 后台任务

- 调度器周期性读取账号状态，负责自动摘要和远程附件入队；手工发起与自动入队共用校验逻辑。附件必须属于当前账号。
- 全局串行领取任务，每次领取有独立租约。过期租约和取消后的迟到结果不能覆盖输入或提交结果。
- 模型请求在数据库事务之外执行。先保存输出，再以账号 generation、工作区/方案、原文和配置版本校验结果；符合预期时提交检查点，否则保存候选或记录失效。
- 重启先处理已落盘但尚未应用的输出。无法确认远端处理结果的任务暂停，等待用户检查后继续，不自动重发模型请求。
- 更换模型连接会暂停该方案的任务并关闭原有自动执行开关；执行过程中连接变化的摘要保留为候选。
- 投递成功代表已经进入账号收件箱，归档仍由用户确认。浏览器、桌宠只显示账号中的收件状态。

## 生产产物与升级

`pnpm build` 生成独立的 `production/` 运行目录：前后端构建产物、编译后的服务器 JS、运行依赖和迁移文件。源码安装与 Docker 都使用它，不携带开发服务器或要求运行时加载 TypeScript。源码启动包装器将数据固定在构建目录外。

首次启动新版本时，将旧 `.wrangler/state/` 中的单个业务数据库以只读方式打开，在账号数据库内导入授权、连接、任务与收件记录。未接收 MCP 事件应用到账号当前状态，不拿旧镜像覆盖工作区；已删除工作区的历史输入保留在 `migration_candidates`。旧 Note 草稿只迁移一次。原业务数据库保持原样，导入完成标记和数据变更在同一事务中提交。

历史迁移校验和保持不变；编译过程不改变旧账号迁移身份。多份旧业务数据库、未知列、未知高版本或损坏数据会拒绝迁移，不能猜测应采用哪一份。继续使用仓库升级脚本的停写、备份、迁移、健康检查与失败恢复流程；成功开放新写入后不能直接用旧快照覆盖。

## 验证与后续范围

自动化用例覆盖超过 200 条无浏览器 MCP 写入、账号隔离、幂等重试、草稿事务、结果重启恢复、过期租约、候选与账号恢复隔离、自动排队、投递密钥撤销、v4 升级重跑。`scripts/check-production.mjs` 直接调用正式构建处理器，并验证编译后的数据库迁移。CI 另在无外网、只读根文件系统的容器中验证 HTTP 8080 登录、业务写入、重启保留数据和内部接口限制。

这轮聚焦数据和执行基础。公共按钮合并、全部辅助偏好的独立 schema、旧只读协议辅助代码清理、全部界面交互验收及真实服务器升级/备份恢复演练仍属于后续清单。已完成任务的结果保留策略和大账号的分段加载需要后续容量测试；不要把功能测试通过解读为容量上限保证。
