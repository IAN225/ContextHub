# 2026-09-09 第四阶段：性能测量与回归

本阶段从 `535549e` 开始，分支为 `codex/frontend-performance`。按实际测量优化长原文时间轴和搜索；继续使用同一套本地前端，没有新增依赖、后端或部署，也未使用子智能体。

## 测量方法

使用本机 Chrome 的独立无头浏览器上下文和 Vinext 生产构建；1280×900px，减少动态效果，关闭页面切换快照。比较前后的脚本、机器和样本生成规则一致，每种规模独立运行三次，以下取中位数。

样本为 208 / 2,000 / 10,000 个完整轮次，每轮含 user 与 assistant 消息，正文长度固定，按固定间隔放入搜索词。对应整个应用记录的 JSON UTF-8 大小约为 0.38 / 3.63 / 18.12 MB；这是样本编码大小，不等于 IndexedDB 实际占用。

`frontend-performance.mjs` 通过 Chrome Performance 指标记录主线程任务、脚本、布局耗时，同时统计时间轴 DOM 节点和 IndexedDB `put` 次数。计时包含界面动作和两帧等待；墙钟耗时还包括自动化往返及输入间隔，不能直接当作所有设备的用户响应时间。未设置固定毫秒断言，避免把机器噪声误判为功能回归。

## 最终版本的结果

表内均为主线程任务耗时（ms），按“优化前 → 优化后”排列。

| 场景 | 208 轮 | 2,000 轮 | 10,000 轮 |
| --- | ---: | ---: | ---: |
| 打开原文 | 63 → 54 | 111 → 44 | 376 → 51 |
| 跳转到中间轮次 | 12 → 13 | 26 → 14 | 83 → 29 |
| 原文筛选 | 11 → 11 | 23 → 18 | 80 → 22 |
| 打开全局搜索 | 27 → 30 | 57 → 28 | 259 → 32 |
| 搜索常见关键词 | 16 → 15 | 25 → 21 | 111 → 36 |
| 已隐藏原文/搜索时切换 Note 标星 | 20 → 25 | 51 → 24 | 200 → 39 |
| 输入并保存 24 个字符 | 405 → 427 | 690 → 491 | 4,927 → 940 |

一万轮场景打开原文的墙钟耗时从 439ms 降至 107ms；输入并保存 24 个字符从 5,118ms 降至 1,514ms。输入脚本每个字符固定间隔 20ms，输入目标是记忆包的自定义摘要，原文和搜索均已访问并隐藏。

时间轴在末尾视图的子节点数量由 50,001 降为 87；运行过程中最多绘制 66 个刻度按钮。小样本保持原有全部刻度，主要收益来自长对话；208 轮的结果有少量增减，不能据此宣称所有操作都变快。

三个规模的 24 字符输入最终均仍写入主记录 24 次。隐藏章节空闲 1.2 秒时，前后都没有产生存储写入，主线程任务约 4–8ms，未发现持续后台忙循环。

## 实际保留的优化

- 超过 400 个筛选结果时，仅渲染当前视口和目标轮次附近各 33 个刻度；省略部分用等宽空间占位。保留原生滚动容器、104px 间距、完整滚动范围、当前轮次与完整消息内容。
- 键盘焦点按真实筛选索引查找按钮，不依赖 DOM 子节点位置；远距离平滑跳转时同时保留正在经过的位置和目标位置。
- 原文筛选结果与轮次编号映射按原文数组复用，避免每次渲染都为每个刻度重新线性查找编号。
- 全局搜索按原文、摘要、Note 数组分别缓存规范化文本。输入、打开结果窗口或修改其他记忆块不再重建全部原文搜索文本；原文修改或状态改变后，由新的数组触发更新。
- 搜索仍统计全部命中，只构造返回数量内的结果对象；空关键词不构造全文数据。缓存使用 WeakMap，不长期强引用已替换的源数组。

## 保存策略的决定

本阶段尝试了短延迟合并自动保存，确实能减少写入，但暂停计时器后立即刷新这一边界场景暴露了待保存修改丢失的风险。离页时异步补写不足以可靠解决，因此该实验已完整撤回。

最终提交没有修改 `repository.ts`、`persistent-session.ts`、`store.ts` 或 `use-hub.ts`。保留现有及时保存、失败重试、原子提交与草稿清理行为。后续若继续降低大手账的写入成本，应先设计分记录存储或可恢复的增量日志，并单独验证迁移、故障及刷新恢复，不能只给现有整份保存加防抖。

在 `demo/` 下启动 `pnpm exec vinext start --hostname 127.0.0.1 --port 3002`，另一个终端执行：

```powershell
$env:PERF_LABEL = 'measurement'
node tests/frontend-performance.mjs
node tests/large-transcript.mjs
```

浏览器脚本需要 Playwright 与已安装的 Chrome；沿用项目现有的 `NODE_PATH` 配置。性能脚本默认测量 208 / 2000 / 10000 轮、各三次，可通过 `PERF_SIZES`、`PERF_RUNS` 调整。`BASE_URL` 默认指向本地生产端口 3002。原始数据写入被忽略的 `demo/outputs/performance/`，本轮汇总见 [测量数据](frontend-performance-results.json)。测试只使用新建的浏览器上下文。

## 仍需关注

- `ui-interactions.mjs` 的既有触屏惯性断言问题与实体 iPhone/Safari 验收仍保留。本阶段的长列表触屏验证覆盖滑动、吸附和定位，不能据此宣称所有设备上的惯性手感已验收。
- 长对话仍完整载入内存，整份应用记录仍逐次持久化；当前优化降低了 DOM 和重复计算成本。更大规模或包含大量附件时，应继续测量数据载入与存储成本。
- 性能结论仅针对上述受控样本和本机环境；本阶段没有引入服务端搜索、分块存储或后台任务。
