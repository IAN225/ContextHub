## 今天完成的修改

- 收敛重复入口：移除收件箱和空状态中的重复收录按钮、Note 空状态的新建按钮；原文 Markdown／原始文本切换统一到当前轮次工具栏，控制该轮全部模型回复。统一搜索、Note 和手账的功能名称。
- 明确收件箱只接收第三方客户端向“发布对话 API”发送消息时带来的上下文。分享链接导入和工作台摘要候选各自使用确认窗口，关闭后可继续处理；旧版待处理数据按来源兼容归类，候选摘要保留手账归属。
- 使用像素小猫作为全局收件箱入口：空闲与抱信两种状态，只统计待归档 API 收件；自由悬浮、鼠标／触屏拖拽、记住位置、限制在可见视口内。拖动不会误打开，点击进入收件箱，键盘方向键也可移动。
- Note 新建和搜索合并到原搜索框位置。左侧笔形图标新建，右侧放大镜向左平移带出输入框，覆盖新建入口并立即聚焦；点击其他位置或按 Escape 清空查询并反向收回。点击搜索结果时先完成选择，再清空查询，保留当前选中的 Note。
- 根据整体纸张风格，将 Note 控件改为透明背景，去掉外框、阴影和玻璃效果，仅保留中间竖线。收起尺寸由 96×44 缩为 80×36px，图标由 19 缩为 17px，展开宽度由 280 缩为 240px；窄屏展开宽度受容器限制。
- 记忆包组件名称与“动态引用／自定义”状态改为同一行，长标题截断并保留完整可访问名称；名称和预览合为一个编辑入口。保留拖动、上下移动及编辑窗口内删除。

## 后续前端重构顺序

1. **先整理状态与持久化边界。** 将 `app/page.tsx` 中的工作区、收件、归档等操作提取为清晰的操作接口和 hooks；页面逐步从整份 `Workspace` 回传更新转为明确的命令。保留 `lib/domain.ts` 的纯业务规则，让 IndexedDB 读写与展示组件分离，为后续后端接入留下替换位置。梳理草稿、自动保存、异步任务与隐藏章节的生命周期，补足旧数据迁移与失败恢复验证。
2. **按组件归属整理 CSS。** 盘点 `app/globals.css` 与 `app/journal.css` 中重复的选择器、媒体查询和覆盖顺序，先提取颜色、间距、层级和动画变量，再逐个迁移到外壳、原文、摘要、Note、记忆包等所属样式。现有 `note-actions.css`、`inbox-pet.css` 可作为局部归属的起点。每次迁移一个区域，删除其已被替代的旧规则，避免继续在文件末尾叠加覆盖。
3. **再拆复杂组件。** 在操作边界稳定后，逐步拆分原文时间轴与轮次详情、摘要工作台、记忆包拖动排序与编辑窗口、导入预览与归档选择。共用行为提取 hooks，共用展示提取小组件，避免仅为了缩短文件而分散同一业务。
4. **最后处理性能和回归。** 测量长对话渲染、持久化频率、搜索和隐藏页任务，再决定是否需要虚拟列表或缓存。回归覆盖 320／390／768／1280px、键盘与鼠标／触屏、减少动态效果、草稿刷新恢复、原文轮次完整性、摘要水位及记忆包引用一致性。

每一步以现有功能、数据和交互保持正确为验收标准，分批提交并单独验证。当前不引入真实后端、不部署网站，也不因 CSS 行数较多就整体重写前端。
